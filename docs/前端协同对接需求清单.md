## 一、致 成员 1（智能合约）：交付需求与接口契约

为了保证前端 MetaMask 能够顺畅调用合约，且在交易 Revert 时向用户展示人话提示，合约端需交付以下内容：

### 1. 合约部署地址交付 (`deployed_addresses.json`)
部署到 **Sepolia 测试网 (Chain ID: 11155111)** 后，请将合约地址更新至 `frontend/static/js/deployed_addresses.json`，格式如下：

```json
{
  "network": "sepolia",
  "chainId": 11155111,
  "deployer": "0x...",
  "timestamp": "2026-10-08T...",
  "contracts": {
    "RoleManager": "0x...",
    "ReceivableToken": "0x...",
    "InvoiceRegistry": "0x...",
    "FinancingPool": "0x...",
    "MockStablecoin": "0x..."
  }

```

### 2. ABI 导出文件同步
若后续合约函数签名或事件有变动，请重新导出 5 个 JSON 文件覆盖至 `frontend/static/js/abi/`：
- `RoleManager.json`
- `ReceivableToken.json`
- `InvoiceRegistry.json`
- `FinancingPool.json`
- `MockStablecoin.json`

### 3. 部署后必须执行的权限初始化配置
在合约部署脚本 `scripts/deploy.js` 中，必须由 Admin 账号调用以下两个设置，否则业务无法走通：
1. `ReceivableToken.setInvoiceRegistry(InvoiceRegistry地址)`（赋予发票合约铸证权限）
2. `ReceivableToken.setFinancingPool(FinancingPool地址)`（赋予资金池合约销毁与托管凭证权限）

### 4. 合约 Revert 报错字符串规范约定
前端已针对以下报错字符串配置了友好的人话中文弹窗翻译，**请务必在 Solidity 中保持完全一致的 `require` 提示语**：

| 触发场景 | 目标合约 | 约定 `require` 报错文本 | 前端友好提示 |
| :--- | :--- | :--- | :--- |
| **重复登记发票** | `InvoiceRegistry` | `"InvoiceRegistry: Invoice already registered"` | “防重拦截：该发票号、买家与金额组合已被登记，无法重复上链！” |

## 二、致 成员 2（后端开发）：REST API 与链上同步需求

所有链上写操作由前端与合约直连，后端主要提供**链下发票文件存储**、**事件同步入库**与**高速查询接口**。

### 1. 统一错误响应结构（强制规范，PRD 第 7 节）
所有 API 出错时，必须返回 HTTP 4xx/5xx 状态码及统一 JSON：
```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "具体的人话错误信息"
  }
}
```

### 2. 核心 REST API 清单与字段契约

#### ① 账户模块
- **`GET /api/me?address=0x...`**
  - **响应**：`{"wallet_address": "0x...", "role": "SUPPLIER", "enterprise_name": "华为供应链", "status": "APPROVED"}`
- **`POST /api/enterprises`**
  - **请求体**：`{"wallet_address": "0x...", "enterprise_name": "...", "contact_person": "...", "role_applied": "SUPPLIER"}`
  - **响应**：`{"id": 1, "status": "PENDING"}`
- **`GET /api/enterprises?status=PENDING`**
  - **响应**：企业申请列表数组
- **`PATCH /api/enterprises/<id>`**
  - **请求体**：`{"status": "APPROVED", "tx_hash": "0x..."}` 或 `{"status": "REJECTED", "reject_reason": "..."}`

#### ② 发票模块
- **`POST /api/invoices/file`** (接收 `multipart/form-data`)
  - **请求入参**：`file` (PDF 附件), `invoice_no`, `supplier`, `buyer`
  - **处理逻辑**：保存 PDF 到 `uploads/` 目录，计算 SHA-256 哈希
  - **响应**：
    ```json
    {
      "file_hash": "0x5d41402abc4b2a76b9719d911017c592...",
      "file_url": "/static/uploads/INV-001.pdf"
    }
    ```
- **`GET /api/invoices?address=0x...&status=PENDING`**
  - **响应**：发票列表数组，每项包含 `id`, `onchain_id`, `invoice_no`, `amount`, `due_date`, `file_hash`, `status`
- **`GET /api/invoices/<id>`**
  - **响应**：单笔发票详情及 PDF 下载地址

#### ③ 凭证与融资模块
- **`GET /api/receivables?holder=0x...`**
  - **响应**：地址当前持有的凭证列表数组（`receivable_id`, `balance`, `buyer_address`, `due_date`, `is_frozen`, `repay_status`）
- **`GET /api/receivables/<id>/history`**
  - **响应**：凭证流转时间轴（发票登记 -> 核心企业确认 -> 拆分转让 -> 质押融资 -> 放款 -> 到期还款）
- **`GET /api/financing?status=PENDING_QUOTE`**
  - **响应**：市场待报价申请列表，包含各资金方的报价数组 `quotes: [{ quote_id, financier_address, discount_rate_bps }]`

#### ④ 仪表盘与审计日志模块
- **`GET /api/dashboard?address=0x...`**
  - **响应**：`{"receivable_total": "...", "pending_invoices_count": 2, "financing_active_amount": "...", "funded_total_amount": "..."}`
- **`GET /api/transactions?address=0x...`**
  - **响应**：当前钱包地址关联的历史交易数组（`action`, `tx_hash`, `block_number`, `timestamp`）
- **`GET /api/events?contract=&name=&address=`**
  - **响应**：链上事件数组（`contract_name`, `event_name`, `block_number`, `tx_hash`, `event_args_json`, `timestamp`）

### 3. Web3.py 链上事件同步器 (Sync Worker) 关键要求
- 后端需要起一个后台线程或循环定时器（建议每 3~5 秒轮询一次 Sepolia 最新区块）；
- 抓取到事件后解析参数并写入 `chain_events` 表，同时自动更新业务表：
  - 监听到 `InvoiceSubmitted` -> 补齐 `invoices` 表的 `onchain_id`；
  - 监听到 `InvoiceConfirmed` -> 将 `invoices.status` 置为 `CONFIRMED`；
  - 监听到 `FinancingFunded` -> 将 `financing_requests.status` 置为 `FUNDED`；
  - 监听到 `Repaid` -> 更新凭证的还款状态为 `REPAID`。

### 4. 静态文件下载与 CORS 支持
- 请确保后端开启 `flask_cors.CORS(app)`；
- 开放上传发票的静态下载路由 `/static/uploads/<filename>`，供核心企业在线查验 PDF。

## 三、三方联调验证路线图 (8 步主线流程)

当合约部署、后端接口上线、前端界面连通后，三方按以下步骤走通联调：

1. **第 1 步 (账号入驻)**：供应商与核心企业提交注册申请 -> 管理员审核并通过 `grantRole` 链上发牌；
2. **第 2 步 (发票上传)**：供应商上传 PDF 发票 -> 后端存文件算哈希 -> 前端调起 MetaMask 提交 `submitInvoice`；
3. **第 3 步 (防重验证)**：故意提交同一张发票 -> 验证合约成功 Revert 且前端弹出防重拦截红字提示；
4. **第 4 步 (核心企业确权)**：核心企业查验发票 -> 点击确认 `confirmInvoice` -> 合约自动铸造等额凭证给供应商；
5. **第 5 步 (拆分转让)**：供应商向二级供应商转让部分凭证 `transferReceivable` -> 验证双方凭证余额同步变动；
6. **第 6 步 (融资竞价与放款)**：供应商发起融资 `requestFinancing` -> 资金方报价 `submitQuote` -> 供应商接受报价 `acceptQuote` (原子化到账)；
7. **第 7 步 (到期还款)**：核心企业向资金池 `repay` 全额面值；
8. **第 8 步 (兑付闭环)**：持有人调用 `redeem` 销毁凭证，1:1 领取稳定币。
